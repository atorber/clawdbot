# Multi-language support (i18n)

## Current state

- **Docs**: Simplified Chinese (zh-CN) is supported via the docs i18n pipeline. The folder `docs/zh-CN/` is **generated** from English sources; do not edit it by hand. Update English docs and glossary in `docs/.i18n/`, then run `scripts/docs-i18n`. See [Docs i18n (zh-CN)](/docs/.i18n/README.md).
- **CLI**: All user-facing strings are in English. No runtime i18n.
- **Control UI (web)**: English only; gateway already sends `locale: navigator.language` for future use.

## Goal

Add multi-language support with **minimal intrusion** into existing code, and add **Simplified Chinese (zh-CN)** as the first additional language.

## Approach

### Principles

1. **Key-based messages**: All user-visible strings are looked up by a stable key (e.g. `overview.gatewayAccess`). Missing keys fall back to English, then to the key itself.
2. **No heavy frameworks**: Use a small in-repo i18n helper and JSON/TS message bundles. No gettext, no react-i18next, no new runtime dependencies.
3. **Scoped rollout**: Start with the **Control UI**; CLI and native apps can follow later using the same key convention and optional shared bundles.
4. **Locale storage**: UI stores the chosen locale in `localStorage` and uses it on load; fallback is `navigator.language` (normalized to `en` or `zh-CN`).

### Scope (phase 1)

| Surface               | Action                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Control UI            | Add i18n layer; add zh-CN; wrap Overview, navigation, and a few high-traffic strings. Language switcher in header or settings. |
| CLI                   | No change (remain English). Optional later: `OPENCLAW_LANG` or config key + thin `t()` only where we print.                    |
| Docs                  | No change (zh-CN already generated).                                                                                           |
| macOS / iOS / Android | Out of scope for this phase.                                                                                                   |

### File layout (Control UI)

- **`ui/src/i18n.ts`**
  - `getLocale()`: read from `localStorage` or `navigator.language` (normalize to `en` / `zh-CN`).
  - `setLocale(locale)`: write to `localStorage`; optionally notify app to re-render (e.g. custom event or callback).
  - `t(key)`: return message for current locale with fallback to `en` then key.

- **`ui/src/locales/en.ts`**
  - Export a flat or namespaced object of key → English string (e.g. `overview.gatewayAccess`, `nav.chat`).

- **`ui/src/locales/zh-CN.ts`**
  - Same keys, Simplified Chinese values.

- **Views**
  - Replace literal strings with `t('key')` only in the views we localize (e.g. Overview, navigation labels). Leave the rest of the code unchanged.

- **Language switcher**
  - Small dropdown or toggle in the top bar or settings (e.g. “EN | 中文”) that calls `setLocale('en')` / `setLocale('zh-CN')` and triggers a re-render.

### Locale resolution

- Supported: `en`, `zh-CN`.
- Browser `navigator.language`: map `zh`, `zh-Hans`, `zh-CN` → `zh-CN`; otherwise → `en`.
- Stored value overrides browser default.

### CLI (optional later)

- Config key or env: e.g. `openclaw config set locale zh-CN` or `OPENCLAW_LANG=zh-CN`.
- Single helper in `src/cli/` or `src/i18n.ts`: `t(key)` that loads the same or a CLI-specific bundle and returns the string. Use only in a few places (e.g. tagline, onboarding) to avoid touching every command.

### Docs

- No change. Keep using the existing docs i18n pipeline and `docs/zh-CN/` as generated output.

## Summary

- **Minimal intrusion**: New files are `ui/src/i18n.ts` and `ui/src/locales/*.ts`; only selected view files get `t('...')` instead of literal strings; one small language switcher in the UI.
- **Simplified Chinese**: Add `zh-CN` bundle and wire it to the locale resolution and switcher.
- **Extensible**: Same pattern can be used later for CLI or other surfaces by reusing keys and adding a small loader where needed.
